# Event: Sprint Retrospective

Right after the review, as the Scrum Master, improve the process itself:

1. From the sprint's real data (QA rework rate, DoD bounces, blocked time,
   delegation latency): what worked well, what did not.
2. Pick ONE concrete, actionable **improvement** for the next sprint — small
   enough to actually happen (continuous improvement: 1% better every sprint).
3. If the improvement requires work, open an issue for it following the
   8-field Definition of Done so it enters the backlog properly.
4. Deliverable: worked-well list, didn't-work list, the chosen improvement and
   where it was recorded (comment/issue link).
